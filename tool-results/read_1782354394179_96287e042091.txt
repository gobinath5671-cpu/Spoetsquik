    11→
    12→Build a full-stack **Inter-College Sports Events Portal** called **SportsFest**.
    13→The platform has two distinct panels:
    14→
    15→| Panel | Purpose |
    16→|---|---|
    17→| **Admin Panel** | Authorized admin feeds upcoming sports events from colleges/schools |
    18→| **User Panel** | Students browse, filter, and register for sports events |

   194→## 4. AUTHENTICATION SYSTEM
   195→
   196→### 4.1 Login Page (`/login`)
   197→
   198→- Clean full-screen page
   199→- `Bebas Neue` large heading: **"SPORTSFEST"**
   200→- Sub: `"Inter-College Sports Events Portal"` in `Cormorant Garamond`
   201→- Single glass card in center with:
   202→  - Email input
   203→  - Password input
   204→  - "Login" button
   205→  - "New here? Register" link (→ `/register`)
   206→- On submit: backend detects if credentials match admin → routes to `/admin/dashboard`
   207→  else → routes to `/user/home`
   208→
   209→### 4.2 Admin Credentials (Hardcoded in `.env`)
   210→
   211→```env
   212→ADMIN_EMAIL=gobinath5671@gmail.com
   213→ADMIN_PASSWORD=Gobin@th.31
   214→```
   215→
   216→> Admin password is also bcrypt-hashed and stored in DB on first server start (seed script).
   217→> Admin cannot self-register; credentials are controlled via `.env`.
   218→
   219→### 4.3 User Registration (`/register`)
   220→
   221→First-time flow:
   222→- Full Name
   223→- Email
   224→- College Name
   225→- Department, Year, Section
   226→- Roll Number
   227→- Password (+ Confirm Password)
   228→- Phone Number
   229→
   230→After register → auto-login → `/user/home`
   231→
   232→On subsequent visits → `/login` → enter email + password → `/user/home`
   233→
   234→### 4.4 JWT Strategy
   235→
   236→- `accessToken` (expires: 1h) — stored in `httpOnly` cookie
   237→- `refreshToken` (expires: 7d) — stored in `httpOnly` cookie
   238→- `/auth/refresh` endpoint silently refreshes access token
   239→- Axios interceptor in frontend handles 401 → auto-refresh → retry request

   362→## 6. BACKEND API — EXPRESS.JS
   363→
   364→### 6.1 Auth Routes `/api/auth`
   365→
   366→| Method | Endpoint | Description | Access |
   367→|---|---|---|---|
   368→| POST | `/register` | User registration | Public |
   369→| POST | `/login` | Login (admin + user) | Public |
   370→| POST | `/logout` | Clear cookies | Private |
   371→| POST | `/refresh` | Refresh access token | Private |
   372→| GET | `/me` | Get current user info | Private |
   373→
   374→### 6.2 Event Routes `/api/events`
   375→
   376→| Method | Endpoint | Description | Access |
   377→|---|---|---|---|
   378→| GET | `/` | Get all events (with filters) | Public |
   379→| GET | `/:id` | Get single event details | Public |
   380→| POST | `/` | Create new event | Admin only |
   381→| PUT | `/:id` | Update event | Admin only |
   382→| DELETE | `/:id` | Delete event | Admin only |
   383→| PATCH | `/:id/status` | Toggle status (upcoming/ongoing/completed) | Admin only |
   384→| GET | `/stats/overview` | Events count by status | Admin only |
   385→
   386→#### Filter Query Params for `GET /api/events`:
   387→```
   388→?status=upcoming|ongoing|completed
   389→?sport=cricket|football|...
   390→?targetAudience=College|School|Both
   391→?date=2025-07-15           (exact date)
   392→?fromDate=...&toDate=...   (date range)
   393→?college=<name>
   394→?format=Knockout|League|Athletics
   395→?search=<keyword>          (eventName or collegeName)
   396→?page=1&limit=12           (pagination)
   397→?sortBy=date|createdAt&order=asc|desc
   398→```
   399→
   400→### 6.3 Registration Routes `/api/registrations`
   401→
   402→| Method | Endpoint | Description | Access |
   403→|---|---|---|---|
   404→| POST | `/:eventId` | Register student for event | User (logged in) |
   405→| GET | `/my` | Get current user's registrations | User |
   406→| GET | `/event/:eventId` | All registrations for an event | Admin |
   407→| GET | `/` | All registrations (with search/filter) | Admin |
   408→| PATCH | `/:id/status` | Approve / Reject registration | Admin |
   409→| GET | `/:id/receipt` | Download registration PDF | User |
   410→| GET | `/event/:eventId/export` | Export as CSV or text file | Admin |
   411→
   412→### 6.4 User Routes `/api/users`
   413→
   414→| Method | Endpoint | Description | Access |
   415→|---|---|---|---|
   416→| GET | `/profile` | Get own profile | User |
   417→| PUT | `/profile` | Update profile | User |
   418→| POST | `/profile/picture` | Upload profile picture | User |
   419→| GET | `/` | Get all users | Admin |
   420→
   421→### 6.5 Upload Route `/api/upload`
   422→
   423→| Method | Endpoint | Description |
   424→|---|---|---|
   425→| POST | `/id-card` | Upload student ID card image (Multer) |
   426→| POST | `/event-poster` | Upload event poster image (Admin) |
   427→
   428→### 6.6 Backend Middleware
   429→
   430→- `authMiddleware` — verify JWT from httpOnly cookie
   431→- `adminMiddleware` — check `role === 'admin'`
   432→- `rateLimiter` — express-rate-limit (100 req/15min per IP)
   433→- `helmet` — security headers
   434→- `cors` — allow frontend origin only
   435→- `morgan` — HTTP logging
   436→- `errorHandler` — global error middleware with consistent JSON error shape

   642→## 9. ADDITIONAL FEATURES (Senior PE Additions)
   643→
   644→### 9.1 Real-Time Status Auto-Update
   645→
   646→Backend cron job (node-cron) runs every hour:
   647→- If `eventDate < now` and `status === 'upcoming'` → set `status = 'ongoing'`
   648→- If `eventDate < now - 1day` → set `status = 'completed'`
   649→
   650→### 9.2 Event Countdown Timer
   651→
   652→On event detail page, JavaScript `setInterval` countdown (days:hours:minutes:seconds)
   653→displayed in `JetBrains Mono`. Hides when event starts.
   654→
   655→### 9.3 Search Autocomplete
   656→
   657→Live search bar (top of events page) with debounce (300ms).
   658→Calls `GET /api/events?search=<query>&limit=5` and shows dropdown suggestions.
   659→
   660→### 9.4 QR Code Registration Verification
   661→
   662→- Each approved registration gets a unique QR code
   663→- QR encodes: `SF-<eventId>-<registrationId>-<registrationCode>`
   664→- Admin can scan QR (using phone camera) to verify on event day
   665→- Future scope: QR scanner page in admin panel
   666→
   667→### 9.5 PDF Registration Slip
   668→
   669→Using `jsPDF`:
   670→- SportsFest logo / header
   671→- Student name, roll no, college
   672→- Event details
   673→- Sport and category
   674→- Registration Code (large, bold)
   675→- QR Code embedded
   676→- "This slip must be presented at the venue" footer
   677→
   678→### 9.6 Email Confirmation (Nodemailer)
   679→
   680→Trigger email on:
   681→1. User Registration → Welcome email
   682→2. Event Registration Submitted → "Your registration is under review"
   683→3. Registration Approved → "Congratulations! You are registered for [Event]" + PDF attached
   684→4. Registration Rejected → "Unfortunately your registration was not approved" + reason
   685→
   686→### 9.7 Bookmarks / Save Events
   687→
   688→- Bookmark icon on every event card and detail page
   689→- Stored in user's profile in MongoDB (`savedEvents: [ObjectId]`)
   690→- Accessible from Profile page
   691→
   692→### 9.8 Toast Notification System
   693→
   694→Custom toast component (no external lib needed):
   695→- Success (white) / Error (dark) / Info (gray)
   696→- Slide-in from top-right, auto-dismiss after 3s
   697→
   698→### 9.9 Skeleton Loaders
   699→
   700→Every list (events, registrations) shows glass skeleton cards while API loads.
   701→No blank screens.
   702→
   703→### 9.10 Responsive Design
   704→
   705→- Mobile-first Tailwind classes
   706→- Dock hides labels on mobile, shows only icons
   707→- Filter sidebar becomes a bottom sheet on mobile
   708→- All tables become card lists on mobile
   709→
   710→### 9.11 404 & Empty States
   711→
   712→- Custom 404 page with `Bebas Neue` large "404" text
   713→- Empty state illustrations for empty events list, empty registrations
   714→
   715→### 9.12 Admin Event Duplicate
   716→
   717→"Duplicate Event" button in admin events table — creates a copy of an event with a new date field blank, for recurring annual events.
   718→
   719→### 9.13 Sports Category Intelligence
   720→
   721→When admin selects a sport (e.g. "Badminton"), the Event Category sub-field
   722→in the student form auto-populates with smart defaults:
   723→- Badminton → Singles, Doubles, Mixed Doubles
   724→- Football → Team (11-a-side), Team (7-a-side)
   725→- Track & Field → 100m, 200m, 400m, 800m, 1500m, 4x100m Relay, Long Jump, High Jump, Shot Put, Javelin Throw
   726→- Cricket → Team (11-a-side)
   727→- etc.

   732→- "Add to Home Screen" on mobile
