    10→    10→## 0. MISSION STATEMENT
    11→    11→
    12→    12→Build a full-stack **Inter-College Sports Events Portal** called **SportsFest**.
    13→    13→The platform has two distinct panels:
    14→    14→
    15→    15→| Panel | Purpose |
    16→    16→|---|---|
    17→    17→| **Admin Panel** | Authorized admin feeds upcoming sports events from colleges/schools |

   194→   194→## 4. AUTHENTICATION SYSTEM
   195→   195→
   196→   196→### 4.1 Login Page (`/login`)
   197→   197→
   198→   198→- Clean full-screen page
   199→   199→- `Bebas Neue` large heading: **"SPORTSFEST"**
   200→   200→- Sub: `"Inter-College Sports Events Portal"` in `Cormorant Garamond`
   201→   201→- Single glass card in center with:
   202→   202→  - Email input
   203→   203→  - Password input
   204→   204→  - "Login" button
   205→   205→  - "New here? Register" link (→ `/register`)
   206→   206→- On submit: backend detects if credentials match admin → routes to `/admin/dashboard`
   207→   207→  else → routes to `/user/home`
   208→   208→
   209→   209→### 4.2 Admin Credentials (Hardcoded in `.env`)
   210→   210→
   211→   211→```env
   212→   212→ADMIN_EMAIL=gobinath5671@gmail.com
   213→   213→ADMIN_PASSWORD=Gobin@th.31
   214→   214→```
   215→   215→
   216→   216→> Admin password is also bcrypt-hashed and stored in DB on first server start (seed script).
   217→   217→> Admin cannot self-register; credentials are controlled via `.env`.
   218→   218→
   219→   219→### 4.3 User Registration (`/register`)
   220→   220→
   221→   221→First-time flow:
   222→   222→- Full Name
   223→   223→- Email
   224→   224→- College Name
   225→   225→- Department, Year, Section
   226→   226→- Roll Number
   227→   227→- Password (+ Confirm Password)
   228→   228→- Phone Number
   229→   229→
   230→   230→After register → auto-login → `/user/home`
   231→   231→
   232→   232→On subsequent visits → `/login` → enter email + password → `/user/home`
   233→   233→
   234→   234→### 4.4 JWT Strategy
   235→   235→
   236→   236→- `accessToken` (expires: 1h) — stored in `httpOnly` cookie
   237→   237→- `refreshToken` (expires: 7d) — stored in `httpOnly` cookie
   238→   238→- `/auth/refresh` endpoint silently refreshes access token
   239→   239→- Axios interceptor in frontend handles 401 → auto-refresh → retry request

   374→   374→### 6.2 Event Routes `/api/events`
   375→   375→
   376→   376→| Method | Endpoint | Description | Access |
   377→   377→|---|---|---|---|
   378→   378→| GET | `/` | Get all events (with filters) | Public |
   379→   379→| GET | `/:id` | Get single event details | Public |
   380→   380→| POST | `/` | Create new event | Admin only |
   381→   381→| PUT | `/:id` | Update event | Admin only |
   382→   382→| DELETE | `/:id` | Delete event | Admin only |
   383→   383→| PATCH | `/:id/status` | Toggle status (upcoming/ongoing/completed) | Admin only |
   384→   384→| GET | `/stats/overview` | Events count by status | Admin only |
   385→   385→
   386→   386→#### Filter Query Params for `GET /api/events`:
   387→   387→```
   388→   388→?status=upcoming|ongoing|completed
   389→   389→?sport=cricket|football|...
   390→   390→?targetAudience=College|School|Both
   391→   391→?date=2025-07-15           (exact date)
   392→   392→?fromDate=...&toDate=...   (date range)
   393→   393→?college=<name>
   394→   394→?format=Knockout|League|Athletics
   395→   395→?search=<keyword>          (eventName or collegeName)
   396→   396→?page=1&limit=12           (pagination)
   397→   397→?sortBy=date|createdAt&order=asc|desc
   398→   398→```
